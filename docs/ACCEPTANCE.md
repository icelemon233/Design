# Design 组件验收记录

当前工作是 Tabs、Transfer 两个样板。产品名为 Design，开发者为 Cinna；保留现有 `@cinna-design` 包名。采用 React 18、TypeScript 严格检查、Vite 和 pnpm 工作区，组件使用自己的 API。

## 本轮范围

- Tabs：无边框胶囊、四方向连体卡片、横向/纵向滚动、键盘、受控状态、禁用、增删、排序和内容状态保留。
- Transfer：双栏列表与中间方向按钮，窄容器上下堆叠，独立搜索、筛选全选、禁用项、受控目标与勾选状态、文案配置。
- 图标：复用已有绘制图标，补齐加号、概览、活动、设置、团队和拖动手柄；文档示例与源码展开按钮使用实际图标。
- 样式归属：Tabs 与 Transfer 各自维护样式，其他组件共用的表面样式移入 shared/surfaces.css。
- 文档：示例展示实际运行源码，API 表对应当前类型和交互，删除重复属性与无效参数。

用户确认这两个可操作预览后，才合并发布并按网页顺序继续其余 47 个组件。其余组件目前均为**本轮待验收**。

## 验证方式

`pnpm check` 覆盖架构、类型、单元、各包构建、导出与 SSR；`pnpm format:check` 检查格式。`pnpm typecheck:samples` 严格检查样板浏览器测试与配置。

安装三种浏览器后，运行 `pnpm test:samples`。矩阵包含三引擎各四种环境：1440×1000/DPR1、768×1024/触控/DPR2、390×844/触控/DPR3，以及 1440×1000/DPR2/减少动画；手机组合状态另查 320px，并在导航前设置尺寸，重新加载后检查页面布局视口和触控目标。Windows 使用一个 worker。CI 按浏览器分开运行，WebKit 的四种环境各用一个独立任务；每个任务使用一个 worker，不自动重试。WebKit 在 Xvfb 虚拟桌面中运行，记录真实帧是否推进，保留原生点击和稳定性检查。

生产子路径验证先执行 `pnpm build:pages`，再设置 `SAMPLE_PRODUCTION=1` 运行测试。已有本地预览服务时，可通过 `SAMPLE_BASE_URL` 指定地址。通过 `SAMPLE_ENGINE` 和 `SAMPLE_PROFILE` 可单独复现某个浏览器或环境。报告在 `playwright-report/samples/`，原始图片、浏览器能力、帧记录和失败轨迹在 `test-results/`。覆盖 24 种组合的几何用例有 120 秒总预算，单次操作仍限时 10 秒。

原生触摸点击通过浏览器收到的 trusted touch/pointer 事件确认，保留 maxTouchPoints 的实际值。Chromium 触控排序使用 CDP 原生触摸移动；Firefox、WebKit 的排序使用真实鼠标指针验证捕获和边缘滚动，其触控模式另验原生点击。未执行实体手机或真实 Safari 验证。

组件局部截图在拍摄时隐藏站点固定导航，避免导航覆盖组件；组件本身保持实际渲染。图片不自动作为视觉通过或用户认可的证据。长名称需滚动到视口中，并检查文字落在所属行内；键盘检查同时核对可见焦点圈，不能只检查 DOM 焦点。

新增的下拉检查使用真实鼠标或触控操作，核对库内浮层、四个位置与三个尺寸选项、中文菜单、44px 触控选项、菜单展开时的 Axe、方向键/End/Enter/Esc/Tab，以及选择后返回的可见焦点。接缝检查切换首个、中间和末尾页签，保留四方向截图。几何检查只能确认位置，截图仍需人工判断接头是否自然。

## 本轮复测修正

- 窄屏操作按钮移到独立一行，给可编辑、可排序的标签保留宽度；纵向标签在窄容器转为横向。
- 修正纵向标签被错误限宽、连体卡片远端圆角接缝，以及触控新增按钮的方形高亮。
- 关闭标签后按实际选中项恢复焦点；只剩禁用项时保留组件内焦点；支持空字符串和保留字作为 key。
- Transfer 的长名称行按内容撑开，在列表内滚动；键盘移动后复选框的可见焦点圈跨浏览器保持一致。
- 320px 检查在设置尺寸后重新加载，核对布局视口确为 320px，页面没有横向溢出。

Windows 本机的 WebKit 无头进程曾出现不推进渲染帧及输入超时，这些运行没有记为通过。CI 的 WebKit 使用虚拟桌面，保留真实帧探针、原生交互和稳定性检查。失败轨迹与后续通过的报告分别保留。

## 之前记录的边界

上一轮的 136 项单元、204 项浏览器检查、三种屏宽截图和 Axe 结果属于历史自动检查。它们没有覆盖本轮要求的三引擎、触控、高 DPI、减少动画与全部交互状态，也没有建立用户确认后的截图基线。旧记录中的“通过”不能继续当作 Tabs 之后所有组件已经完善的结论。

这一轮按功能、人工视觉检查和用户确认分别记结果；未检查、失败或跳过的状态不记作通过。
